Registrar versão observada do modelo, data, modo, SHA e release completa. Usar conversas novas e arquivos sintéticos com valores inventados para teste, preservando originais. Para cada caso usar ledger EXPECTED_REQUIREMENTS / PLANNED_REQUIREMENTS / EXECUTED_CRITERIA / RESULTS / PROJECTED_RESULTS / REPORTED_RESULTS. Campo não observado fica NÃO OBSERVADO, nunca preenchido por inferência. Ausência de observabilidade não prova omissão.

### Exceção de duplicidade do comprovante

Em EXT-02, duplicação de anexos de evidência deve ser distinguida de dois registros candidatos do comprovante corrente. O contrato 02a exige exatamente um candidato forte: dois comprovantes correntes distintos podem causar ARCHITECTURAL_BLOCKER legitimamente. Se uma cópia idêntica for unificada na normalização derivada, a rastreabilidade das duas origens deve permanecer. O ensaio não exige invariância de resultado quando a mutação altera a cardinalidade dos candidatos fortes; verifica o comportamento declarado para cada representação.
