###############################################################################
# 08_execution_pipeline.txt
# BASE DE CONHECIMENTO
# EXECUTION PIPELINE
# VERSION 4.2
###############################################################################

OBJECTIVE

This document defines the mandatory execution sequence of the Knowledge Base.

It does not define Requirements, Criteria, Nonconformities or Report rules.

Its only purpose is to define the execution order.

###############################################################################
# EXECUTION CONTRACT
###############################################################################

The executor acts exclusively as the execution engine of the Knowledge Base.

The executor shall not:

- create Requirements;
- create Criteria;
- create Nonconformities;
- create documentary evidence;
- create technical conclusions;
- reinterpret the Knowledge Base;
- use external knowledge;
- modify execution results.

Every output shall originate exclusively from the active Knowledge Base.

###############################################################################
# EXECUTION SEQUENCE
###############################################################################

Execute the following phases exactly in this order.

Do not skip phases.

Do not change the execution order.

###############################################################################
# PHASE 1
# LOAD
###############################################################################

Load the active Knowledge Base.

Load:

00_engine

01_entities

02_requirements

03_table1

04_table4

05_nonconformities

06_report_operacional

07_report_auditoria

09_rde_specification

If any document is unavailable:

STOP EXECUTION.

###############################################################################
# PHASE 2
# DOCUMENT EXTRACTION
###############################################################################

The exclusive purpose of this phase is to construct the
Representação Documental Estruturada (RDE).

The RDE shall be constructed exactly as specified by:

09_rde_specification.

Every extracted documentary fact shall be represented using the canonical representation defined by the RDE specification.

This phase shall never perform execution.

Do not:

- evaluate Requirements;
- evaluate Criteria;
- determine compliance;
- determine noncompliance;
- determine applicability;
- generate Nonconformities;
- generate operational alerts;
- generate technical conclusions.

###############################################################################
# DOCUMENT STATE
###############################################################################

For each document required by the active Knowledge Base, determine exactly one documentary state:

PRESENT

ABSENT

INCOMPLETE

UNVERIFIABLE

Store the documentary state for later execution.

###############################################################################
# DOCUMENTARY EXTRACTION
###############################################################################

Extract documentary information exactly as documented.

Do not reinterpret documentary content.

Do not classify documentary relevance.

Do not determine whether documentary information satisfies any Requirement.

Do not determine whether documentary information creates any Nonconformity.

Do not determine whether documentary information requires MANUAL_REVIEW.

Do not generate execution results from documentary content.

Documentary statements contained in submitted documents are not execution results.

They are only documentary evidence.

###############################################################################
# ATTRIBUTE EXTRACTION
###############################################################################

Extract documentary attributes required by the active Knowledge Base.

Identify, when documentally verifiable:

- REGISTERED
- SIGNED
- APPROVED
- PAID
- RT_NAME
- RI_NAME
- ADDRESS
- AREA
- DATES
- IDENTIFIERS

When evaluating SIGNED:

Search only for documentally verifiable digital or electronic signatures.

Do not infer the existence of a signature from:

- the presence of a signature field;
- the document type;
- another signed document.

When no documentally verifiable digital or electronic signature can be confirmed,

store

SIGNED = MANUAL_REVIEW.

Do not store SIGNED = FALSE solely because no signature was identified.

No documentary attribute may be inferred from another documentary attribute.

Every stored attribute shall be directly supported by documentary evidence contained in the administrative process.

###############################################################################
# RDE CONSTRUCTION
###############################################################################

Construct the Representação Documental Estruturada (RDE)
using the extracted documentary entities and attributes.

The RDE shall conform exactly to:

09_rde_specification.

The completed RDE becomes immutable.

No further documentary extraction is allowed.

END RDE CONSTRUCTION.

###############################################################################
# PROCESS MEMORY
###############################################################################

The Process Memory shall be built exclusively from the
Representação Documental Estruturada (RDE).

The RDE is the only documentary input authorized for Process Memory construction.

Process Memory shall never:

- interpret documentary evidence;
- determine documentary relevance;
- evaluate Requirements;
- evaluate Criteria;
- generate execution results;
- generate Nonconformities.

Once the RDE has been completed, it becomes immutable.

Process Memory shall consume only the immutable RDE.

No documentary attribute may be created, updated, removed or reinterpreted after Phase 2.

Requirements, Criteria and Report generation shall consume Process Memory only.

Do not retry documentary extraction during later phases.

###############################################################################
# EXECUTION BOUNDARY
###############################################################################

No documentary statement may influence the execution directly.

Every execution result shall originate exclusively from the following execution chain:

Process Memory

↓

Requirement

↓

Criterion

↓

Execution Result

↓

Nonconformity (when FAIL)

Documentary evidence alone shall never generate:

- PASS
- FAIL
- MANUAL_REVIEW
- NOT_APPLICABLE
- Nonconformity
- Operational Alert

unless explicitly evaluated by an applicable Criterion.

Document extraction is complete only after every submitted document has been processed.

END PHASE 2.

###############################################################################
# PHASE 3
# ENTITY NORMALIZATION
###############################################################################

Normalize the entities contained in the RDE using 01_entities.

Merge equivalent entities.

Preserve the original documentary source.

No inference is allowed.

The normalized entities contained in the RDE
shall be prepared for Process Memory construction.

###############################################################################
# PHASE 4
# EXECUTION PLAN
###############################################################################

Build Process Memory exclusively from the normalized RDE.

Only after the Process Memory is complete, determine the applicable
Requirements.

Determine which Requirements are applicable.

Select exclusively the Criteria referenced by those Requirements.

Only documentary attributes contained in the Process Memory may determine Requirement applicability.

Resolve every VALIDATE declared by the applicable Requirements.

Associate the corresponding Nonconformities.

No Requirement may be created.

No Criterion may be created.

###############################################################################
# PHASE 5
# TABLE EXECUTION
###############################################################################

Execute all applicable Requirements using the Process Memory.

After Requirement validation, execute the referenced Criteria.

Execute Table 1.

Complete every applicable Criterion in Table 1 before starting Table 4.

Each Criterion shall produce exactly one result.

Every applicable Requirement shall be evaluated exactly once.

Allowed results:

PASS

FAIL

NOT_APPLICABLE

MANUAL_REVIEW

No other result is allowed.

Criteria shall consume Process Memory only.

Criteria shall never create, update or reinterpret documentary attributes.

###############################################################################
# PHASE 6
# RESULT CONSOLIDATION
###############################################################################

Consolidate all Criterion results.

Associate Nonconformities only with FAIL results.

Criterion results shall remain immutable after consolidation.

Associate operational alerts only with MANUAL_REVIEW results.

Operational Alerts are internal execution artifacts.

Before Report Generation,

every Operational Alert shall be translated into exactly one
MANUAL_REVIEW report entry.

Operational Alert identifiers shall never appear in user-visible reports.

MANUAL_REVIEW results shall never generate Nonconformities.

MANUAL_REVIEW shall propagate to every dependent Criterion unless an explicit documentary rule defines otherwise.

Do not modify previous results.

No report section shall be generated before Result Consolidation completes.

###############################################################################
# PHASE 7
# REPORT GENERATION
###############################################################################

Generate the operational report using only:

Do not expose Requirements, Criteria or internal identifiers in the
operational report.

The operational report shall not reinterpret execution results.

06_report_operacional.

If the user explicitly requests:

- audit
- auditoria
- relatório completo
- modo auditoria
- anexo técnico
- validação
- homologação

append the report defined by:

07_report_auditoria.

The Technical Annex shall describe only the execution actually performed by the inference engine.

The audit report shall not introduce new documentary findings after Result Consolidation.

###############################################################################
# EXECUTION RULES
###############################################################################

Never execute phases out of order.

Never return to a previous phase.

Never modify results produced in previous phases.

Never replace documentary evidence with model knowledge.

Never infer absent information.

When documentary evidence cannot be verified, return exactly:

Informação insuficiente para verificar.

The report generation phase shall never trigger additional documentary analysis.

If additional documentary evidence would be required to change a result, the execution shall terminate with the previously consolidated results.

###############################################################################
# TRACEABILITY
###############################################################################

Every reported result shall be traceable through the complete execution chain:

Source document

↓

Representação Documental Estruturada (RDE)
↓

Process Memory

↓

Requirement

↓

Criterion

↓

Reported result

Every reported result shall preserve this traceability chain.

No execution phase may bypass any element of the traceability chain.

No reported information may exist without complete documentary traceability.
